# llm-orch API keys
# =================
# One entry per line: `<label>: <key>`.  The label is used in logs and
# metrics to identify the key holder; the key data must never appear in
# logs.  Blank lines, `#` lines and a whitespace-preceded ` # …` suffix on
# a line are comments.  Revocation = delete the line.
#
# Recommended: store the SHA-256 digest of the token instead of the token
# itself, so a leaked file (backup, wrong permissions, pasted into a ticket)
# hands out nothing usable, and llm-orch's own memory holds only digests:
#
#   label: sha256:<64 hex chars, case-insensitive>
#
# Generate a key (prints the token once, plus the line to paste here):
#
#   llm-orch keygen --label work-desktop
#
# Convert this file in place (dry run without --write; keeps comments and
# alignment; the plaintext is then unrecoverable):
#
#   llm-orch hash-apikeys -k apikeys.txt --write
#
# Check what a client's token maps to (read from stdin, never argv):
#
#   printf '%s' "$TOKEN" | llm-orch verify-apikey -k apikeys.txt
#
# Hash ONLY machine-generated tokens.  SHA-256 is not a password KDF: a GPU
# tries ~10^10 guesses/s, so a human-chosen token is cracked in seconds.
# Start a `sha256:` line with `$argon2id$` if you ever need a real KDF — that
# form is reserved and rejected by this build with a clear message.
#
# Serve with `--require-hashed-apikeys` once every line is hashed, and
# plaintext entries are refused instead of merely tolerated.
#
